# Homework 02_03: Сортировка слиянием

## Описание алгоритма:

>
> ### Массив делится на две половины до тех пор, пока размер подмассива не станет равным 1. 
>
> ### После сортировки левой и правой половин выполняется слияние с использованием дополнительного буфера для временного хранения результата.
>
> ### Для ускорения на почти отсортированных массивах добавлена проверка границы половин: если последний элемент левой половины меньше или равен первому элементу правой, merge пропускается.
>
> ### Базовая реализация алгоритма, нет оптимизаций для очень маленьких подмассивов, для которых можно использовать более простые алгоритмы, например линейную сортировку вставками, что уменьшит расходы рекурсии и merge.

---

## Временная сложность:

>
> ### Алгоритм рекурсивно делит массив на две равные части, сортирует каждую из них отдельно, после чего выполняет линейное слияние двух отсортированных половин.На каждом уровне рекурсии выполняется обработка всех элементов массива во время операции слияния. При этом глубина рекурсии растёт логарифмически, так как массив на каждом шаге делится пополам.В результате общее количество операций пропорционально произведению размера массива на количество уровней рекурсии. Это даёт временную сложность порядка `n log n` в среднем и худшем случаях.
>
> ### В лучшем случае (если массив уже отсортирован или почти отсортирован) проверка `arr[mid] <= arr[mid + 1]` позволяет пропустить операцию слияния для многих подмассивов. В таком сценарии количество операций становится линейным и стремится к `O(n)`.

---

## Пространственная сложность:

>
> ### Используется один буфер размером n: `O(n)`.
>
> ### Дополнительно используется стек рекурсии глубиной log n: `O(log n)`.
>
> ### Доминирующей является память под буфер, поэтому итоговая пространственная сложность `O(n)`.

---

## Асимптотика:

>
> ### Временная сложность: `O(n log n)` в худшем и среднем случаях. 
>
> ### Пространственная сложность: `O(n)`.
